# 会话产物归拢与命名

**给 AI 编程会话用的工作区整理方法** —— 每个会话一个专属文件夹，收尾时按**实际内容**改名，并刷新索引。

随 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 的 skill 插件分发；**三个脚本是纯 bash，不依赖 DSH** —— Claude Code / Codex / Cursor 或任何 agent 都能直接用。

---

## 它解决两个问题（不是假设，是真踩出来的）

### 问题一：产物散落 → 工作目录失控

多个会话共用一个工作目录，跑几天之后就变成了这样：

```
3.46 GB / 514 个顶层条目
  ├─ 305 个散落在顶层的截图   1.jpg、10.png、12_small.png …（只占 59 MB）
  ├─ 42 个会话产物目录        帧序列 318M、宣传视频 484M、素材库 2.2G …
  └─ 剩下的才是真东西         构建工具、源码、文档
```

**关键点：乱的不是体积，是颗粒度。** 那 305 张截图只占 59 MB —— 但它们和源码、文档、
构建工具**平铺在同一层**，于是「哪张图还有用、哪个目录能删」谁也说不清，
**最后只能整个目录一起放着不敢动**。

**二次伤害**：这些文件通常没有版本控制，删错不可恢复 —— 「乱」直接变成「不敢清理」。

### 问题二：名字对不上内容

把东西归好类之后，还有第二个坑：

> 「有些时候我们自己很忙，直接开干了，而且一个会话中不一定只有一个主题，
> 所以结束后或者交接后再放一段时间，自己就不是很清楚具体内容了。」

**三段根因**：

1. **命名时机错** —— 名字是在"开干前"起的，而内容是在"干完之后"才确定的。
2. **会话多主题** —— 一个名字概括不了整天做的事。
3. **人的记忆会淡** —— 交接或隔几周回来，光看文件夹名想不起来。

**所以：命名必须分两段。**

## 它做什么

### 1. 归拢：每个会话一个专属文件夹

```
~/会话产物/
  2026-10-11-律师端UI定稿与v0.1.12发版/
  2026-10-10-深鲸画布上架插件市场/
  2026-10-09-鸿蒙涉外文书排版/
  INDEX.md                    ← 自动生成的索引
  _归档/                      ← 收起来的旧会话
```

截图、验证脚本、临时下载、中间产物**一律进去**，不写工作目录根、不写 `/tmp`、不写 `$HOME` 根。

### 2. 命名：开干时临时名 → 收尾按实际内容改名

| 阶段 | 做什么 |
|---|---|
| **开干时** | `sess.sh <关键词>` 建文件夹，名字粗糙没关系 |
| **收尾时** | agent 回顾整个会话**实际做了什么**，`sess-rename.sh --apply <旧> <新>` 改名 |

脚本**自动保留原日期前缀** —— 日期是「会话发生的时间」，不该被改名弄丢。

### 3. 索引：几个月后还能查

```markdown
| 日期 | 会话 | 体积 | 文件 | 摘要 |
|---|---|---|---|---|
| 2026-10-11 | 律师端UI定稿与v0.1.12发版 | 4.0K | 1 | 律师端 UI 定稿（查看原文/术语标注/按钮态）… |
```

名字概括主线，`README.md` 写全内容，`INDEX.md` 汇总 —— 三层各司其职。

## 安装

### 作为 DSH 插件

```bash
dsh plugin add @deepwhale-cn/dsh-session-artifacts
```

装完重启 DSH，技能自动可用。

### 只用脚本（任何 agent）

三个脚本是纯 bash，拷走即可：

```bash
git clone https://github.com/feely0208/dsh-session-artifacts.git
cp dsh-session-artifacts/bin/*.sh /usr/local/bin/     # 或任何在 PATH 里的目录
```

## 用法

```bash
# 1) 会话首次要存东西时：建专属文件夹（幂等）
DIR=$(sess.sh 律师端辉光)
echo "$DIR"
# → /Users/you/会话产物/2026-10-11-律师端辉光

# 2) 收尾时：按实际内容改名（保留原日期）
sess-rename.sh --apply 律师端辉光 律师端UI定稿与v0.1.12发版
#   旧: 2026-10-11-律师端辉光
#   新: 2026-10-11-律师端UI定稿与v0.1.12发版

# 3) 刷新索引
sess-index.sh
# → 已刷新 ~/会话产物/INDEX.md
```

### 命令速查

| 命令 | 作用 |
|---|---|
| `sess.sh <主题>` | 建（或复用今天的）并打印路径 —— **幂等**，多调几次不会堆目录 |
| `SESS_NEW=1 sess.sh <主题>` | 同一天确实另开一个会话时强制新建（加 `-2`/`-3`） |
| `sess-rename.sh --list` | 列出所有会话文件夹（日期/体积/文件数/内容提示）|
| `sess-rename.sh --apply <旧> <新>` | 按实际内容改名（保留原日期；支持模糊匹配；重名拒绝）|
| `sess-rename.sh --apply <旧> <新> --dry` | 只看会改成什么 |
| `sess-index.sh` | 刷新 `INDEX.md` |

根目录可用 `SESS_ROOT` 覆盖（默认 `~/会话产物`）。

## 命名规范

| ✅ 好名字 | ❌ 差名字 | 为什么 |
|---|---|---|
| `律师端辉光与官网发版` | `UI调整` | 太泛，三个月后认不出 |
| `深鲸画布上架插件市场` | `画布` | 只说对象没说做了什么 |
| `鸿蒙涉外文书排版` | `工作` | 等于没命名 |

- **动词 + 对象**：做了**什么**
- **主线优先**：多主题时取主线，不要贪全
- **多主题确实并列**时用 `+` 连：`官网发版+插件市场上架`
- **不要塞日期**（脚本保留原日期）
- **不要用泛词**：工作、杂项、整理、临时、各种、其他

### 多主题会话怎么处理

**正解是分工，不是把名字撑长**：

```
名字    = 索引键（要好记、要短）   →  取主线
README  = 内容清单（要全）        →  写全
INDEX   = 总索引（要能搜）        →  自动生成
```

```markdown
# 2026-10-11 · 律师端UI定稿与v0.1.12发版     ← 名字概括主线

## 这个会话做了什么                          ← README 写全
1. 鸿蒙律师端「查看原文」对齐桌面端
2. 桌面端 UI 规范整改
3. 移植「深鲸辉光」（三次迭代）
4. v0.1.12 发版上官网
5. 官网源码纳入版本控制
6. 清理 9.2 GB 冗余
```

## 为什么这件事值得做（不是强迫症）

1. **AI 会话的产物天生是碎的** —— 截图、脚本、临时包，一次几十上百个。
   没有归宿，它们就只会堆在工作目录里。
2. **留痕对很多行业是硬要求** —— 法律、财务、医疗的工作记录需要可追溯。
   有组织、可按时间和主题检索的会话产物，本身就是**审计友好的基础设施**。
3. **成本极低** —— 建文件夹是一条命令，改名是一条命令。
   而事后整理一个 500 项的目录，成本高一个量级（这个仓库就是这么来的）。
