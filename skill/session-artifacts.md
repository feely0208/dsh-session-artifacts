# 会话产物归拢与命名

> 本技能随 `@deepwhale-cn/dsh-session-artifacts` 分发。
> 三个脚本在 `<bin 目录>` 下：`sess.sh` / `sess-rename.sh` / `sess-index.sh`。
> **它们是纯 bash，不依赖 DSH** —— Claude Code / Codex / Cursor 等任何 agent 都能直接用。


**两条主线**：
1. **归拢** —— 会话产出的一切临时东西都进 `~/会话产物/<日期>-<主题>/`，不散落。
2. **命名** —— 开干时随手起个临时名，**收尾时按会话实际内容改名**，并刷新索引。

---

## 零、为什么有这条规则（2026-10-11，真实后果）

### 0.1 乱：产物散落 → 目录失控

`/Users/mac/DeepSeek Harness/` 是多个会话共用的工作目录。跑了几天之后：

```
3.46 GB / 514 个顶层条目
  ├─ 305 个散落在顶层的截图   1.jpg、10.png、12_small.png …（只占 59 MB）
  ├─ 42 个会话产物目录        05-帧 318M、抖音-30秒 484M、官网-画布专题页 2.2G …
  └─ 剩下的才是真东西         hvigor（构建工具）、site-migration（官网源码）、文档
```

用户原话：**「就是太多了，看起来乱乱的」**。

**关键点：乱的不是体积，是颗粒度。** 305 张截图只占 59 MB，但它们和源码、文档、
构建工具平铺在同一层，于是「哪张还有用」谁也说不清，**最后整个目录不敢动**。

**二次伤害**：这些文件没有版本控制，删错不可恢复 —— 「乱」直接变成「不敢清理」。

### 0.2 忘：名字对不上内容

归拢之后还有第二个问题。用户的原话：

> 「有些时候我们自己很忙，直接开干了，你我都忙，而且一个会话中不一定只有一个主题，
> 所以结束后或者交接后再放一段时间，自己就不是很清楚具体内容了」

**三段根因**：
1. **命名时机错** —— 名字是在"开干前"起的，而内容是在"干完之后"才确定的。
2. **会话多主题** —— 一个名字概括不了整天做的事。
3. **人的记忆会淡** —— 交接或隔几周回来，光看文件夹名想不起来。

**所以：命名必须分两段。**

## 一、硬性规则

### 1.1 每个会话一个专属文件夹

```
~/会话产物/
  2026-10-11-律师端辉光与官网发版/
  2026-10-10-深鲸画布上架插件市场/
  2026-10-09-鸿蒙涉外文书排版/
  INDEX.md                    ← 索引（由 sess-index.sh 生成）
  _归档/                      ← 收起来的旧会话
```

**命名**：`<YYYY-MM-DD>-<主题>`
- 日期用会话**开始**那天（改名时**保留**原日期，别弄丢）
- 主题 6–14 个字，动词 + 对象（见 2.2）

### 1.2 以下东西**一律**进会话文件夹

| 类型 | 例子 |
|---|---|
| 截图 / 录屏 | 界面验证图、真机截图、对比图、before/after |
| 验证脚本 | 一次性的检查脚本、冒烟脚本、数据探查脚本 |
| 临时下载 | 抓下来的包、参考图、对照素材 |
| 中间产物 | 帧序列、导出的草稿、格式转换的中间文件 |
| 分析输出 | 临时报表、dump、日志片段 |

### 1.3 以下东西**不进**会话文件夹（它们有正式归宿）

| 类型 | 该去哪 |
|---|---|
| 最终交付物 | 产品仓库 / 正式素材目录 |
| 已建仓的源码 | 它的仓库（如官网源码在 `site-migration/`）|
| 构建工具 / 依赖 | 不动（如 `hvigor`）|
| 长期维护的文档 | 正式的文档目录 |
| 技能 / 配置 | `~/.dsh/skills/` 等 |

### 1.4 会话结束时处理

- **先移走交付物**（进正式目录）
- **再改名**（按实际内容 —— 见第二节）
- **再刷新索引**
- 会话文件夹本身：**可以整删** —— 这是它的设计目的
- 舍不得删的压进 `_归档/`

## 二、命名：两段式（本 skill 的核心）

### 2.1 第一段：开干时给临时名

**用脚本，不要手拼路径。**

```bash
DIR=$(bash <sess.sh 路径> <主题简称>)
```

**不要提前建**（有些会话不产生任何文件）。等到真要存第一个文件时再建。

临时名**可以是粗糙的**（首个需求的关键词就行）—— 因为第二段会改。
如果连主题都还没成形，用能想到的 2–6 个字，甚至 `待命名` 都可以。

### 2.2 第二段：收尾时按**实际内容**改名

**时机**（任一触发）：
- 用户说「收尾」「结束」「整理一下」「归档」
- 准备写交接文档（`session-handoff`）时
- 会话明显收束（大任务做完、不再有新产出）
- 用户说「这个会话是干嘛的来着」—— **这就是信号**

**动作**：回顾整个会话，问自己三个问题：

1. **这个会话实际做成了什么？**（不是"一开始打算做什么"）
2. **主线是哪一件？**（多主题时挑产出最多/最重要的）
3. **有没有一个 6–14 字的说法能让三个月后的自己一眼认出？**

然后改名：

```bash
bash <sess-rename.sh 路径> --apply <旧名> <准确主题>
```

脚本自动保留原日期前缀；支持模糊匹配旧名；重名会拒绝。

**命名规范**：

| ✅ 好名字 | ❌ 差名字 | 为什么 |
|---|---|---|
| `律师端辉光与官网发版` | `UI调整` | 太泛，三个月后认不出 |
| `深鲸画布上架插件市场` | `画布` | 只说对象没说做了什么 |
| `鸿蒙涉外文书排版` | `工作` | 等于没命名 |
| `官网源码纳入版本控制` | `杂项` | — |

- **动词 + 对象**：做了**什么**
- **主线优先**：多主题时取主线，不要贪全
- **多主题确实并列**时，用 `+` 连：`官网发版+插件市场上架`
- **不要塞日期**（脚本保留原日期）
- **不要用泛词**：工作、杂项、整理、临时、各种、其他

### 2.3 多主题会话怎么办

**正解**：名字取主线 + **README 写全**。

名字是**索引键**（要好记、要短），README 是**内容清单**（要全）。
不要试图把一个会话的所有事塞进文件名 —— 那样名字会长到没法用。

```markdown
# 2026-10-11 · 律师端辉光与官网发版        ← 名字概括主线

## 这个会话做了什么                        ← README 写全
1. 鸿蒙律师端「查看原文」对齐桌面端
2. 桌面端 UI 规范整改
3. 移植「深鲸辉光」到律师端（三次迭代）
4. 律师端 v0.1.12 发版上官网
5. 官网源码纳入版本控制
```

### 2.4 刷新索引

改名后（或任何时候）刷新索引：

```bash
bash <sess-index.sh 路径>
```

生成 `~/会话产物/INDEX.md`：**日期 / 会话名 / 体积 / 文件数 / README 摘要** 一页看全。
这是「隔几个月回来也不知道这个文件夹是什么」的最终答案。

### 2.5 脚本速查

| 命令 | 作用 |
|---|---|
| `sess.sh <主题>` | 建（或复用今天的）并打印路径 —— **幂等** |
| `SESS_NEW=1 sess.sh <主题>` | 同一天确实另开一个会话时强制新建（加 `-2`/`-3`） |
| `sess-rename.sh --list` | 列出所有会话文件夹（日期/体积/文件数/内容提示）|
| `sess-rename.sh --apply <旧> <新>` | 按实际内容改名（保留原日期）|
| `sess-rename.sh --apply <旧> <新> --dry` | 只看会改成什么 |
| `sess-index.sh` | 刷新 `INDEX.md` |

根目录可用 `SESS_ROOT` 覆盖（默认 `~/会话产物`）。

## 三、怎么用（会话里的动作）

### 3.1 建文件夹（首次产生临时产物时）

```bash
SESSION_DIR=$(bash <sess.sh 路径> <主题简称>)
echo "$SESSION_DIR"
```

### 3.2 写文件时

- 截图、脚本、下载 → **全部写绝对路径到 `$SESSION_DIR`**
- ❌ 不要写 `./shot.png`、`/tmp/xxx.png`、`~/xxx.png`
  （`/tmp` 会跨会话堆积，2026-10-11 实测清出 1.6 GB）

### 3.3 收尾时

1. 交付物移走
2. **回顾会话 → 改名**（2.2）
3. **刷新索引**（2.4）
4. 报告：里面有什么 / 交付物是否已移走 / 能否整删

---

## 四、给 AI 会话的执行要求

1. **要存第一个截图/脚本/临时文件时**，先用 `sess.sh` 建 `$SESSION_DIR`
2. **所有临时产物只写 `$SESSION_DIR`**，不写工作目录根、不写 `/tmp`、不写 `$HOME` 根
3. 交付物放正式位置，**不要留在会话文件夹**
4. **收尾时必须做命名那一步** —— 不要跳过。即使名字看起来还行，也回顾一遍；
   如果会话实际做的主线跟临时名差得远，**改掉**
5. 收尾时写/更新会话文件夹里的 `README.md`（至少含「做了什么」和「能不能删」）
6. **不主动删别人的东西**：只动 `$SESSION_DIR`；工作目录的清理**先列清单再动手**

## 五、与 `session-handoff` 的分工

| skill | 管什么 |
|---|---|
| `session-handoff` | 会话**交接文档**（给下一个会话接手用）→ `~/Public/会话交接文档/` |
| 本 skill | 会话**过程产物**（截图/脚本/临时文件）+ **命名与索引** → `~/会话产物/` |

两者互补：交接文档是「留下来的」，本 skill 管「用完就扔的」+「怎么找得到」。
**写交接文档时，顺手把会话文件夹改名 + 刷索引** —— 这两个动作天然该挨在一起。
